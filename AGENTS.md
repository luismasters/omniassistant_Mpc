# AGENTS.md

Spanish, Windows-only desktop AI assistant ("Argus"). All code, comments, tests, and docs are written in **Spanish** (rioplatense) — keep that convention.

## Run

- Active entry point: `python main_web.py` (PyWebView Web HUD). **`main_gui.py` is DEPRECATED** — do not add features there.
- Requires a `.env` in repo root with `GEMINI_API_KEY` to talk to Gemini. Without it the app doesn't crash: `config.py` degrades (`GEMINI_API_KEY == ""`) and `modulos/ia.py` responds with a friendly notice (see `tests/test_config_api_key.py`).
- Windows-only: code uses `pywin32`, Win32 `ctypes`, `WorkerW` reparenting, XInput, `screeninfo`. Nothing runs headless outside Windows.
- Other standalone tools: `gestor_boveda.py` (memory vault CLI), `mapeo_control_prueba.py` (gamepad diag), `test_emo_face.py` (EMO face prototype).

## Tests

- **Always use the venv:** `venv\Scripts\python.exe -m pytest`. Plain `python` is 3.11 without pytest; the venv is 3.13 with pytest 9.1.1. 257 tests, ~20s, offline — none need API keys.
- `pytest.ini`: `testpaths = tests`, `pythonpath = .`. `tests/conftest.py` sets `OMNASSISTANT_NO_FILE_LOG=1` (also useful for CI/headless, disables the rotating file handler).
- Tests must **stub `modulos.ia` / `modulos.memoria`** like `tests/test_controlador_acciones.py` does: importing them pulls `config` and, for `memoria.py`, downloads a SentenceTransformer model from HuggingFace at import time. Keep tests offline-fast that way.

## Architecture

- `modulos/` = backend logic. `modulos/ia.py` is the AI router (Gemini/DeepSeek/Groq, streaming, MCP). `config.py` holds `estado` (global thread-safe state) — mutate via its locked methods, never assign `config.estado.contexto_chat` directly.
- `gui/` is the PyWebView frontend (`index.html`, `app.js`, `emo_face.js`, `styles.css`). `modulos/web_bridge.py` is the JS↔Python bridge.
- Skills live in `modulos/skills/<nombre>/`. Each skill is auto-loaded by `modulos/skills/gestor_skills.py`: `instructions.md` is **required** (skipped if missing), `SKILL.md` and `ejemplos.md` optional. Keyword activation is hardcoded in `gestor_skills.py`. Stub the heavy imports (`config`, `modulos.ia`, `modulos.memoria`) via `sys.modules` monkeypatching (see `test_controlador_acciones.py`).
- Adding a skill requires `instructions.md` (required) plus optional `SKILL.md`/`ejemplos.md`; activation keywords are edited in `gestor_skills.py`.
- Verificación web (Arquitectura C+D): el LLM decide con la señal `[WEB: SI]`/`[WEB: NO]` + `[CONSULTA: ...]`; Python solo ejecuta. Ver `modulos/senal_web.py` (ocultador de streaming, parser, fusión con `buscar:` legacy, marcador `[TEMA WEB ANTERIOR]`) y `modulos/mensajes_web.py` (segunda generación con evidencia y persistencia separada). Detalle completo en `ARQUITECTURA_VERIFICACION_WEB.md`.
- Contrato de olvidos (Opción E, hallazgo H.1): "olvidar" **NO es retroactivo** sobre el contexto activo. `resolver_olvidar()` (en `modulos/resumen_memoria.py`) invalida perfil/ChromaDB y registra el tombstone; eso veda la reaparición futura vía recuperación automática (`modulos/recuperador_memoria.py`), extracción y consolidación de perfiles (filtros por `esta_olvidado`). `contexto_chat` y `evidencia_web` **NO se depuran al olvidar**: son el registro de la conversación/snippets y no conservan vínculo a `origen_id`. NO implementar una purga retroactiva por coincidencia textual (imprecisa, inventa una relación mensaje↔memoria que no existe). Tests que fijan el contrato: `tests/test_contrato_olvido_no_retroactivo.py`.
